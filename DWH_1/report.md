reversed - это отдельная операция возврата с отрицательной суммой, связанная с исходной операцией через orig_txn_id.

Найти reversal и исходную операцию, посмотрев orig_txn_id:
``` Python
con.sql("""
	SELECT
	    r.txn_id AS reversal_txn_id,
	    r.orig_txn_id,
	    o.txn_id AS original_txn_id,
	    o.status AS original_status,
	    r.amount AS reversal_amount,
	    o.amount AS original_amount
	FROM raw.transactions r
	LEFT JOIN raw.transactions o
	    ON o.txn_id = r.orig_txn_id
	WHERE r.status = 'reversed'
	LIMIT 1
""")
```

## 3. Зерно: 

Вариант `б` (одна строка = одна уникальная операция (после удаления дублей), любого статуса), потому что он позволяет сохранить все уникальные операции после устранения технических дублей. При этом в факте остаются approved, declined и reversed, поэтому по нему можно как рассчитывать оборот, так и анализировать долю отклонённых операций. Для расчёта фактических трат необходимо дополнительно фильтровать операции по статусу и типу операции;

### Р1: 
```
Отказы (declined) и возвраты (reversed) попадают в вашу таблицу фактов? Если да — что обязан помнить каждый, кто напишет по ней sum(amount)?
```
Ответ:
```
Да, попадают. При выбранном зерне одна строка соответствует любой уникальной операции, поэтому отказы и возвраты сохраняются в факте. При расчёте оборота нельзя бездумно использовать SUM(amount) по всем строкам: для конкретного показателя необходимо учитывать статус и тип операции.
```

### Р2: 
``` 
Операция в долларах совершена в субботу, а ЦБ публикует курс только по будням. По какому курсу переводить её в рубли? Почему join rates on rates.date = дата_операции — ошибка, и сколько операций он потеряет?
```
Ответ:
```
Используем последний опубликованный курс на дату, не превышающую дату операции. На субботу берем курс пятницы, потому что в субботу записи ЦБ нет, следовательно, операция не найдёт соответствующий курс и потеряется при обычном JOIN.
```
